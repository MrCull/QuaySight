# Full-photo versus original-resolution damage crops ? ticket #120

Checked: 30 October 2026. Based on `46ab4f6`, following the [45-call baseline](jev-box-baseline-2026-10-30.md). This is research on three tuning photographs, with provisional visual review and no independent per-defect labels. It does not measure validated detection accuracy.

## Controlled method

`node scripts/jev-crop-experiment.mjs --live --repeats 3 --output docs/research/evidence/jev-crop-2026-10-30` uses a transient `OPENROUTER_API_KEY` (or `--key-stdin`). The key is held in Node memory, excluded from browser evaluation and saved requests, and redacted from any response before saving. Omit `--live` for a free preparation run. Use a new output folder; evidence files cannot be overwritten. Authentication/credit/rate/transport failure stops the experiment, without retries.

The matrix is three photos ? three exact baseline prompt variants ? three repeats ? three image conditions = 81 requests. Each request pairs Noul target presence with Box localisation. Photos and descriptions match the baseline: grey side dent, CAI torn door and ambiguous/distant JDLU side. Questions and state instruction are copied verbatim from committed baseline JSON. Model is explicitly `typesafe/jev-1.14`.

Conditions are fresh full photo; a crop around the fixed baseline `specific-1` raw box with zero margin; and the same seed with the existing .35 long-side padding. Seed selection occurs before any new calls, including low-confidence JDLU as a control rather than an accepted defect. ?Raw? identifies seed padding, not a guarantee that the returned rectangle covers the whole defect. Existing `cropRegion` can widen a narrow crop to fit provider aspect limits; the recorded actual integer rectangle is authoritative. The image service `cropPhoto` decodes and cuts the **original bytes**, using existing upright EXIF decoding, canvas JPEG quality .9 and model limits. No saved prepared photo is substituted as its crop source. Original/prepared hashes, actual rectangle, output size and per-axis scales are retained in the manifest. Output has upright pixels and no EXIF; normalized answers map through actual crop edges to canonical upright original dimensions using `mapCropBox`.

All originals already fit the provider limits: 900?600 grey, 800?600 CAI, 1080?1440 JDLU. Cropping therefore magnifies existing pixels; this corpus does **not** test recovery of original detail lost by full-photo downsampling. No synthetic geometry case establishes small-defect model accuracy.

Area retained is image area, **not** irrelevant area or defect coverage. With no independent target contours those fractions cannot establish either. In particular the grey seed covers only a focal segment of the extended crease: a second box inside that seed cannot recover the excluded extent. Padding adds context and unrelated panel area, and remains a distinct analysis crop rather than a new defect boundary.

## Replay and review

[Immutable request evidence](evidence/jev-crop-2026-10-30/manifest.json) records exact prompts, response JSON, requested/resolved model, usage, provider cost and latency. Replace the request's image reference with the manifest JPEG's data URL to reconstruct the payload. Never add authorization to evidence. This runner does not enable live test suites or alter historical responses.

`node scripts/jev-crop-review.mjs docs/research/evidence/jev-crop-2026-10-30 .scratch/crop-review` regenerates all contact sheets offline: one returned-box sheet on each sent image and one canonical mapped sheet on the corresponding full photo. Every repeat is shown, including rejected/absent-target boxes. No provider calls or credential are needed. Provisional visual assessments below are author review, not expert ground truth; no IoU, precision, recall or target coverage percentage is claimed.

## Results and decision

All 81 requests succeeded and resolved to `typesafe/jev-1.14-20261014`. They used 291,533 input and 3,078 output tokens, cost $0.012244386 and took 28.252 seconds in total. All returned rectangles had valid geometry. The provisional baseline guards (presence at least .80 and box confidence at least .50) accepted 18 of 18 full-photo responses for the two clear targets, but none of their 36 crop responses. None of the 27 JDLU control responses passed. These thresholds were tuned on the baseline photographs and are not independently calibrated.

| Photo | Full presence / box confidence | Raw crop | Padded crop |
| --- | --- | --- | --- |
| CAI | .89–.98 / .58–.69 | .62–.76 / .14–.22 | .81–.94 / .27–.39 |
| Grey | .91–.99 / .53–.67 | .35–.50 / .08–.15 | .84–.94 / .13–.48 |
| JDLU | .33–.46 / .15–.22 | .35–.43 / .04–.06 | .28–.42 / .04–.16 |

Visual review found that the raw CAI crop selected a placard; its padded crop approximately located the torn flap, albeit at low box confidence. Grey raw crops narrowed the focal region of the longer crease. The samples already fit the provider limits, so this experiment does not rule out a benefit when cropping recovers detail from a larger original. It provides no evidence to add a crop-based localisation pass to production now.
